Warum der Monatsabschluss noch Excel braucht

Eine Tabelle im Monatsabschluss kann wie das Problem aussehen. Oft ist sie der erste Ort, an dem Führungskräfte das eigentliche Problem klar sehen: Niemand besitzt die Übergabe zwischen Systemen.

Es sind zwei Tage bis zum Monatsabschluss. Sales exportiert Pipeline-Änderungen aus dem CRM. Finance zieht Rechnungen aus dem ERP. Operations ergänzt eine Liste von Ausnahmen aus einem Postfach. Die Sitzung beginnt mit einem einfachen Problem: Die Zahlen stimmen nicht überein.

Die naheliegende Antwort ist, Excel die Schuld zu geben. Die Tabelle ist fragil. Formeln sind versteckt. Versionen wandern per E-Mail. Irgendjemand hat immer die aktuellste Datei auf dem Desktop.

Aber Excel ist meist nicht der erste Fehler. Es ist der Ort, an dem frühere Fehler sichtbar werden. Die hilfreiche Frage lautet nicht, warum es die Tabelle gibt. Die hilfreiche Frage lautet, warum vertrauenswürdige Systeme noch eine Tabelle brauchen, bevor Führungskräfte entscheiden können.

Excel ist oft ein Symptom, nicht das System

Die meisten B2B-Unternehmen wählen Excel nicht als Reporting-Architektur. Sie landen dort, weil die offiziellen Systeme jeweils einen Teil der Wahrheit halten.

Das CRM kennt das kommerzielle Versprechen. Das ERP kennt Rechnung, Warenbewegung oder Auftragsstatus. Finance weiss, was abgeschlossen, abgegrenzt, korrigiert oder erklärt werden muss. Der Monatsabschluss wird zum Ort, an dem diese Sichten in eine Zahl gezwungen werden.

Darum löst ein neues Reporting-Tool das Problem selten allein. Ein Dashboard kann eine sauberere Sicht zeigen. Es kann aber nicht entscheiden, welches System ein Feld besitzt, wann eine Korrektur gültig ist oder wer eine Ausnahme freigeben muss.

Der Diagnosewechsel: Fragen Sie nicht zuerst, wer die Tabelle gebaut hat. Fragen Sie, welche Übergabe versagt hat, bevor die Tabelle nötig wurde.

Woher die Tabelle im Monatsabschluss kommt

Dasselbe Muster taucht in vielen operativen Berichten auf. Es ist nicht dramatisch. Meist ist es eine Kette kleiner Entscheidungen, die im Moment sinnvoll waren.

1. Eine Zahl hat mehrere Definitionen

Umsatz, Backlog, offene Aufträge, gebuchte Verkäufe, gelieferter Wert und Marge können je nach Team etwas anderes bedeuten. Sales zählt einen Auftrag vielleicht bei Bestätigung. Finance zählt ihn bei Rechnung. Operations achtet darauf, ob er tatsächlich geliefert werden kann.

Kein Tool kann diese Definitionen still abstimmen. Wenn die Definition nicht geklärt ist, wird die Tabelle zum Verhandlungstisch.

2. Korrekturen passieren ausserhalb des Quellsystems

Eine Kundenhierarchie wird in einer Tabelle korrigiert. Ein Produktcode wird in einer E-Mail berichtigt. Eine Lieferausnahme steht in einer Teams-Nachricht. Der Bericht stimmt für diesen Monat, aber das Quellsystem lernt nichts.

Im nächsten Monat kommt dieselbe Abweichung zurück, weil die Korrektur als Reporting-Arbeit behandelt wurde und nicht als Systemarbeit.

3. Ausnahmen haben keinen Besitzer

Jedes Unternehmen hat Ausnahmen. Das Problem ist nicht, dass es sie gibt. Das Problem entsteht, wenn niemand ihren Weg zurück in den Prozess besitzt.

Wenn eine Ausnahme in einem Postfach liegen kann, ohne Protokoll die Hand wechselt oder von der Person gelöst wird, die den Kontext noch kennt, braucht der offizielle Bericht immer eine menschliche Abstimmungsschicht.

4. Zeitliche Unterschiede sind nicht sichtbar

Ein CRM-Update, eine ERP-Buchung, eine Lagerbestätigung und eine Finance-Korrektur passieren selten exakt gleichzeitig. Das ist normal. Entscheidend ist, ob das Geschäft den zeitlichen Unterschied sehen und verstehen kann.

Wenn Timing unsichtbar ist, diskutieren Führungskräfte über Genauigkeit, obwohl die eigentliche Frage die Reihenfolge ist.

Ein praktischer Check: eine Zahl rückwärts verfolgen

Beginnen Sie nicht mit der gesamten Reporting-Landschaft. Beginnen Sie mit einer Zahl, die im Monatsabschluss Reibung erzeugt. Verfolgen Sie sie rückwärts vom Managementbericht bis zum ursprünglichen Ereignis.

Stellen Sie fünf Fragen:

  1. Wo wird diese Zahl zuerst erzeugt? Nennen Sie das System und das Geschäftsereignis, nicht nur den Bericht.
  2. Wer kann sie später ändern? Dazu gehören manuelle Anpassungen, Importe, Korrekturen und Ausnahmelisten.
  3. Welches System darf recht haben? Wenn zwei Systeme einander überschreiben können, kommt der Konflikt zurück.
  4. Wo wird die Korrektur erfasst? Eine korrigierte Tabelle genügt nicht, wenn das Quellsystem falsch bleibt.
  5. Wer sieht eine Abweichung vor dem Monatsabschluss? Wenn die erste Warnung die Abschlusssitzung ist, ist der Prozess zu spät.

Diese Übung ist bewusst eng. Eine Zahl reicht, um das Betriebsmodell sichtbar zu machen. Sie zeigt, ob das Problem Definition, Eigentum, Timing, Zugang oder fehlende Rückmeldung ins Quellsystem ist.

Verkleinern Sie die Abstimmung, bevor Sie sie automatisieren

Automatisierung kann helfen, aber erst nachdem das Geschäft weiss, was automatisiert werden soll. Wenn der heutige Prozess auf Urteilen beruht, die in einer Tabelle versteckt sind, verschiebt Automatisierung den Konflikt nur schneller.

Der bessere Weg ist, die Abstimmung zuerst kleiner zu machen.

  • Definieren Sie die Quelle der Wahrheit für die Felder, die den Bericht steuern.
  • Machen Sie wiederkehrende Tabellenkorrekturen zu nachvollziehbaren Systemänderungen.
  • Erstellen Sie eine Ausnahmeliste mit Besitzer, Status und Entscheidungsregel.
  • Zeigen Sie zeitliche Unterschiede explizit, statt sie als Datenfehler zu behandeln.
  • Nutzen Sie Excel als Diagnosewerkzeug, nicht als dauerhafte Betriebsschicht.

Das Ziel ist nicht, jede Tabelle zu entfernen. Das ist selten realistisch und oft nicht nötig. Das Ziel ist, eine Tabelle nicht mehr als einzigen Ort zu nutzen, an dem das Geschäft wahr wird.

Die eigentliche Frage im Monatsabschluss

Wenn der Monatsabschluss noch von Excel abhängt, hat das Unternehmen vielleicht kein Tabellenproblem. Vielleicht hat es ein Problem mit Daten-Eigentum.

Das ist lösbar, aber es muss richtig benannt werden. Sobald Führungskräfte wissen, welche Übergabe versagt, welches System die Zahl besitzt und wohin Korrekturen zurück müssen, ändert die Tabelle ihre Rolle. Sie ist nicht mehr das System of Record. Sie wird, was sie sein sollte: eine vorübergehende Prüfung eines Prozesses, den das Unternehmen kontrolliert.

Wenn ein Bericht noch neu aufgebaut werden muss, bevor die Führung ihn vertraut, sagen Sie mir, welcher Bericht zuerst bricht. Ich helfe Ihnen, die Übergabe dahinter nachzuzeichnen.
